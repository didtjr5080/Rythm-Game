# Rythm-Game 그래픽 깨짐 수정 및 전시 안정화 작업 지시서

대상은 [didtjr5080/Rythm-Game](https://github.com/didtjr5080/Rythm-Game)의 PyQt6 데스크톱 게임이다. 분석 기준은 [main 커밋 42bc7ec](https://github.com/didtjr5080/Rythm-Game/commit/42bc7ec700136efd5c1ba240771262af249110fe)이다. 실제로 문제가 난 EXE의 버전과 SHA256을 먼저 기록하고, 작업 시작 시 소스 HEAD와 대조한다.

## 1. 목표 및 구현 범위

1. 손으로 조작할 때 **픽셀이 깨져 보이는 현상**을 재현하고 수정한다. 메뉴의 커서 잔상·배경 조각, 게임의 카메라·골격 표시, 전체 화면 전환 시 깨짐을 각각 확인한다. **설정 저장 완료 직후 시작 화면의 비율이 깨지는 현상**은 저장 동작을 기준으로 별도 재현하고 P0에서 수정한다.
2. 전시 흐름인 **실행 → 곡 선택 → 플레이 → 결과 → 재시작**에서 화면 멈춤, 로딩, 장치 오류를 줄인다.
3. 기존 5레인 손가락 매핑, 주먹의 레인 해제, 실제 EMG와 모의 EMG 구분, 수축당 최대 한 번 판정, 판정 허용 구간과 음악 동기를 회귀 검사한다. 메뉴의 펼침 이동·한 번 접기 클릭·두 번 접기 스크롤과 마우스·키보드 조작도 검사한다.
4. 기준 커밋의 `AGENTS.md`는 도구의 작업 범위를 문서화로 제한한다. 아래 구현 항목은 후속 수정 작업의 범위다.

### P0. 그래픽 깨짐 재현 및 수정

1. **깨지는 픽셀의 위치를 기록한다.** 전시 PC의 실제 EXE에서 먼저 실행한다. 화면 녹화 전후 5초, 문제 프레임 번호, 화면 이름, Windows 배율, 화면 모드·해상도, 카메라 요청·실제 해상도, 반전, EMG 모드, 연결 모니터를 남긴다. 화면 녹화에 잡히지 않으면 모니터를 외부에서 촬영한다. 녹화가 렌더링에 영향을 줄 수 있으므로 성능 측정은 녹화 없이 다시 한다.

   | 비교 | 재현 절차 | 분기 기준 |
   |---|---|---|
   | 손 커서 | 카메라 활성 상태에서 마우스만 사용한 경우와 손 커서를 사용하는 경우를 비교한다. 손 커서를 버튼·목록·모서리 위로 이동하고, 접기 대기·스크롤·숨김을 반복한다. 동일 좌표의 모의 `hand_sample()`로 실물 카메라 없이 재현한다. | 커서 주변만 깨지면 오버레이의 합성과 갱신 영역을 먼저 본다. |

2. **커서 잔상 재현 시** `app/ui/hand_cursor.py`의 `CursorRing`부터 수정한다. 펜 외곽·안티앨리어싱 여유·`SCROLL` 문자열 좌우 전환을 포함한 실제 이전/현재 그리기 범위를 계산하고, 해당 영역의 아래 배경도 다시 합성되게 한다. 숨김·분리·크기 변경 시 이전 영역을 복원한다. 동일 위치·상태에서 불필요한 갱신을 건너뛰고, 표시 및 Z 순서 변경은 필요할 때만 수행한다. Qt의 기존 배경 전파와 지역 갱신으로 먼저 검증한다. 잔상이 지속되면 화면 합성 방식과 작은 커서 위젯 방식을 비교해 재현 테스트를 통과하는 최소 변경을 적용한다. 투명 마우스 히트 테스트와 실제 OS 커서 위치도 검사한다.

4. **전체 화면 깨짐 재현 시** `MainWindow.apply_window_settings()`의 창 플래그·숨김·재표시와 `GameWidget.paintEvent()`를 조사한다. 100%·125%·150% 배율과 전시 모니터에서 재현한 뒤 논리 좌표와 장치 픽셀 비율을 검증한다. 정적 레이어를 캐시한다면 크기·배율·화면/테마 변경에서 무효화하고, 캐시를 켠 상태의 첫 프레임과 화면 복귀 프레임을 비교한다.
5. **그래픽 회귀 검사를 만든다.** 기존 `WorkOrder/verify_hand_cursor.py`의 모의 입력을 재사용한다. 고정 배경에서 커서를 A→B→숨김으로 이동시키고 이벤트 처리 후 A 영역이 배경으로 복원됐는지 비교한다. 색상 상태 전환, 우측 가장자리의 스크롤 문자열, 화면 크기 변경을 포함한다. 영상은 좌우가 구분되는 합성 프레임과 알려진 좌표로 맞춤 영역을 검증하고, 반전 왕복과 프레임 손실을 주입한다. Qt 오프스크린 검사에 더해 Windows EXE 실화면에서도 재검증한다.

#### P0 추가. 설정 저장 완료 직후 화면 비율 복구

1. **실제 저장 버튼으로 재현한다.** 시작 화면→설정→저장 후 시작 화면의 첫 표시 프레임과 레이아웃 안정화 후 프레임을 비교한다. 변경 없이 저장, 음량만 변경, 카메라 해상도만 변경, 화면 해상도만 변경, 창 모드만 변경을 각각 시험한다. 설정을 저장하지 않고 돌아오는 동작도 대조한다. 마우스와 손 클릭을 모두 사용한다. 증상을 창 크기 변화, 패널 잘림·겹침, 이미지 늘어남, 손 커서와 클릭 위치 불일치로 구분한다.
2. **설정 적용 순서와 창 상태를 정리한다.** `SettingsScreen.save_and_back()`과 `MainWindow.apply_window_settings()`에서 검증된 저장 전후 `window_mode`·`resolution`을 비교한다. 표시 설정이 같으면 창 플래그와 크기·위치를 다시 적용하지 않는다. 값이 바뀌면 기존 손 클릭 이벤트 전달이 끝난 뒤 시작 화면 교체와 창 모드 적용을 한 경로에서 처리한다. 설정 화면의 크기 제약이 남은 상태에서 시작 화면의 목표 크기를 결정하지 않도록 하고, 실제 모드 전환 때만 필요한 플래그를 바꾼다. 전체 화면에서 창 모드로 돌아갈 때 일반 창 상태를 명시적으로 복원한 후 저장된 클라이언트 크기를 적용한다. 화면보다 큰 요청은 사용 가능한 영역에 맞춰 조정한다. 카메라 설정값은 영상 세션에 적용하며 창 크기에는 사용하지 않는다.
3. **창 크기와 그리기 비율을 분리한다.** 저장 전후 요청 해상도, 실제 창 및 중앙 위젯 크기, 레이아웃 최소 크기, 모니터의 사용 가능 영역, DPI 배율, 최종 창 상태를 기록한다. 창 모드의 해상도는 Qt 논리 단위 기준의 클라이언트 크기로 확인하고, 전체 화면은 실제 모니터에서 얻은 중앙 위젯 크기를 기준으로 그린다. 시작 화면의 패널·버튼은 실제 가용 폭·높이에 맞게 배치하고, 작은 창에서 필요한 경우 줄바꿈·스크롤로 주요 버튼에 접근할 수 있게 한다. 게임의 16:9 판정 영역은 기존 단일 배율과 중앙 여백을 사용하며, 카메라 영상은 원본 종횡비에 맞춘다. 손 커서 오버레이와 클릭 좌표는 새 중앙 위젯의 논리 좌표에서 일치해야 한다. 정적 화면 캐시가 있다면 실제 크기·DPI 변경 시 갱신한다.
4. **저장 경로 회귀 검사를 추가한다.** 테스트용 설정 파일과 모의 장치로 실제 `save_and_back()` 경로를 호출하고, 시작 화면 교체 직후 첫 paint와 이벤트 처리 후에 중앙 위젯·주요 버튼·오버레이 범위를 검증한다. 모드 변경 없는 저장에서 사용자 조정 창 크기·위치가 유지되는지 확인한다. Windows 배포 EXE에서 창·테두리 없는 창·전체 화면을 왕복하고 1280×720(16:9), 1440×900(16:10), 800×600(4:3)과 100%·125%·150% 배율을 비교한다. 전시 모니터와 배율이 다른 보조 화면이 있다면 화면 이동 후에도 확인한다. 실제 테스트 화면에 들어가는 크기로 조정된 경우 요청값과 실측값을 모두 기록한다.

### P1. 렉과 로딩 줄이기

6. **구간별로 시간을 잰다.** `perf_counter_ns()`로 GUI 틱 간격·틱 실행 시간·paint 시간, 카메라 읽기·추론·픽스맵 변환, 데이터 저장, 음원 디코딩, 화면 전환을 각각 기록한다. 캡처 완료→해당 결과의 첫 GUI 표시 시간과 카메라 결과의 연속 간격도 별도로 기록한다. 같은 결과를 여러 GUI 틱에서 읽으면 한 건으로 집계한다. 프레임별 콘솔 출력 대신 메모리에 집계하고 구간 종료 또는 일정 주기에 p50/p95/p99·최대값·표본 수를 작성한다.
7. **먼저 표시 비용을 낮춘다.** 전시 초기 시험 조합은 화면 출력 1280×720, 카메라 640×480, AR 배경 끔이다. 실제 전시 해상도에서도 검증하고, 640×480이 손을 자주 놓치면 1280×720 캡처와 비교해 선택한다. `show_camera_debug`가 카메라 디버그 레이어를 실제로 제어하도록 연결하고, 표시가 꺼진 소비자의 색 변환·영상 복사를 건너뛴다. `InputFusion`의 다른 소비자를 확인한 뒤 중복 변환을 줄인다. 정적 배경 캐시와 장식 업데이트 빈도 조정은 렌더링 계측상 효과가 있을 때 적용한다. 음악 시간과 입력·판정 루프는 장식 렌더링과 독립적으로 유지한다.
8. **추론 지연이 남으면 기존 워커 안에서 줄인다.** 정상 추적과 손 재탐색의 추론 횟수·p95를 비교한다. 재탐색 반복이 원인일 경우 현재 방향을 우선하고 보정/반대 방향 후보를 제한된 빈도로 분산하는 방식을 비교한다. 좌우 손, 손 가림, 어두운 현장, 두 손이 잡힐 때의 재획득과 레인 정확도를 함께 검증한다. 기존 최신 결과 한 칸, 카메라 세션 공유 및 네이티브 해제 직렬화를 재사용한다.
9. **전시 곡은 사전에 준비한다.** 1~2곡을 실제 EXE에서 등록하고 대응하는 채보를 미리 생성·검증한다. 전시 중 곡 교체나 채보 생성도 지원해야 한다면 분석·생성·저장을 작업 스레드로 옮기고 진행 상태와 실패 원인을 표시한다. 곡 변경·화면 이탈 후 이전 작업 완료가 현재 선택을 덮어쓰지 않도록 요청 ID를 확인한다. 채보 파싱 및 음원 디코딩이 느리면 제한된 캐시·사전 로딩을 적용하고, 음원과 채보의 변경 시각 또는 내용이 달라지면 무효화한다. 시작 기준은 기존 재생 시계와 실제 음원 시작에 맞추고 빠른 종료·재시작 시 이전 음원이 재생되거나 새 음원을 끊지 않게 검증한다.
10. **전환 시 I/O 병목을 처리한다.** 게임→결과 지연이 확인되면 결과 화면을 먼저 표시하고 세션 JSON/CSV와 결과 파일은 스냅샷 기반 작업으로 저장한다. 임시 파일 후 원자적으로 교체하며, 같은 초에 연속 플레이해도 식별자가 충돌하지 않게 한다. 저장 중·실패 상태를 표시하고 실패 후 재시도 가능하게 한다. 목록 갱신이 병목이면 전 항목 파싱을 지연하거나 캐시하고, 잘못된 JSON 한 건으로 전체 목록이 멈추지 않게 한다.

### P2. 장애 복구 및 Windows 전시 리허설

11. **장치 장애를 주입한다.** 카메라 점유·분리·재연결, MediaPipe 초기화 실패, COM 포트 변경·센서 분리, 스피커 출력 오류, 누락·손상 음원과 채보, 쓰기 실패를 시험한다. 화면은 계속 조작할 수 있어야 하고 작업자는 설정에서 재시도하거나 검증된 대체 경로로 이동할 수 있어야 한다. 카메라 사용 불가 시 숫자키 1~5 경로를 안내한다. 실제 EMG가 끊기면 입력을 무효화한다. SPACE는 운영자가 명시적으로 모의 모드를 선택했을 때 동작하게 한다. 장치 검색/열기·핸드셰이크가 GUI를 막는 것으로 측정되면 해당 작업을 백그라운드에 두고, 재연결 직후 이전 수축 상태가 판정에 쓰이지 않는지 확인한다.
12. **전시 EXE로 최종 시험한다.** 현재 `build_windows.ps1`의 폴더형 빌드와 `--self-test`를 사용한다. 전체 ZIP을 로컬의 쓰기 가능한 폴더에 해제해 `_internal`을 함께 둔다. 네트워크를 끊고 사용할 카메라·EMG·스피커·외부 모니터를 연결한 상태에서 실행한다. 전시 곡·채보·설정 복원 방법과 검증된 이전 ZIP을 현장 운영자에게 전달한다. 오류 발생 시 Windows 오류 이벤트와 `app/data/logs/runtime-YYYYMMDD.log`를 대조한다. EXE에서는 `_internal/app/data/logs/`를 확인한다.

## 4. 완료 검증 체크리스트

아래 숫자는 전시 PC에서 사용할 1차 합격선이다. 동일 장비·빌드 설정·음원·채보로 기준판과 수정판을 비교한다. 권장 비교 조건은 손 고정 30초, 연속 이동 30초, 전시 곡 한 판 전 구간, 메뉴 전환 및 플레이 반복이다. 허용치를 수정하는 경우 측정값과 전시 운영에 미치는 영향을 남긴다.

- [ ] **그래픽** · 메뉴/설정/결과 목록 각 20회 커서 왕복과 20회 화면 왕복에서 잔상·검은 블록·남은 `SCROLL` 문구 0건. 손 가림과 반전 왕복에서 영상과 실측 골격의 좌우 불일치 또는 구세대 골격 표시 0건.
- [ ] **설정 저장 후 비율** · 변경 없는 저장과 음량·카메라 해상도만 바꾼 저장은 각각 5회 반복하고, 실제 전시 출력에서 창↔테두리 없는 창↔전체 화면 전환 및 저장을 10회 반복한다. 저장 후 첫 표시부터 패널 잘림·겹침, 영상 늘어남, 클릭 위치 어긋남이 모두 0건이어야 한다. 표시 설정이 그대로이면 저장 전후 창 크기·위치가 일치하고, 해상도 변경 후에는 설정 모드에 맞는 실제 크기 또는 가용 영역으로 조정된 크기가 기록되어야 한다. 앱 재실행 후에도 저장된 모드와 비율을 확인한다.
- [ ] **게임 프레임** · 정상 플레이 3회에서 실제 paint 간격 p95 ≤ 25ms, p99 ≤ 40ms를 목표로 한다. 플레이 중 100ms 초과 GUI 멈춤 0건. 메뉴 전환·로딩은 별도 구간으로 집계한다.
- [ ] **손 반응** · 안정적으로 손이 보이는 상태에서 캡처 완료→최초 표시 p95 ≤ 100ms 목표. 손 가림 해소→첫 유효 추적의 지연을 따로 기록한다. 메뉴 한 번 접기 지연은 450ms 이중 접기 대기를 포함해 따로 보고한다.
- [ ] **로딩** · 콜드 실행→메뉴 조작 가능 ≤ 5초, 사전 준비한 곡 선택 후 시작 입력→첫 실제 오디오 ≤ 2초, 곡 종료→결과 화면 조작 가능 ≤ 1초를 목표로 한다. 실행 5회, 곡 시작·결과 전환 10회로 상한을 확인한다. Windows 외부 촬영이나 오디오 루프백으로 실제 출력 시점을 확인하고, 내부 재생 요청 시각은 별도로 기록한다.
- [ ] **입력·판정** · 같은 모의 채보 및 타임스탬프에서 판정·점수·콤보 비교가 일치한다. 주먹은 레인을 비우고, 수축당 한 번만 판정한다. 두 번 접기에서 첫 클릭이 취소되며, 화면 전환·손실·ESC 후 대기 클릭이 발생하지 않는다. 장치를 뽑았을 때 오클릭·오판정 0건.
- [ ] **음악·저장·복구** · 빠른 시작/뒤로/재시작에서 이전 곡의 뒤늦은 재생 0건. 음원·채보·장치 오류에서 화면 조작과 복구 조작이 가능하다. 정상 플레이의 세션·결과 파일이 누락·덮어쓰기 없이 저장되고 다시 읽힌다.
- [ ] **장시간 안정성** · 전시 환경에서 60분 연속, 완주·결과·재시작 20회 이상을 확인한다. 강제 종료·처리되지 않은 예외·카메라 동시 열기 0건. 메모리·핸들·작업 스레드가 반복 횟수에 따라 지속적으로 누적되는지 기록하고, 원인을 확인해 해소한다.
- [ ] **배포 확인** · 기존 검사, 새 픽셀 회귀 검사, 최종 배포 EXE 자체 검사와 물리 장치 리허설을 모두 통과한다. 각각의 테스트 명령과 결과를 남긴다. 설정 저장 후 화면 비율 회귀 검사도 실행한다.

## 5. 검증 명령 및 제출물

기존 환경으로 아래 항목을 소스 기준판과 수정판에서 실행한다. `verify_camera_resolution.py`는 스크린샷을 생성하므로 검증용 작업 폴더에서 실행한다. `--self-test`는 물리 장치 리허설과 별개로 기록한다.

```powershell
$python = ".\.venv311\Scripts\python.exe"
& $python WorkOrder/verify_hand_cursor.py
& $python WorkOrder/verify_result_hand_cursor.py
& $python WorkOrder/verify_live_video.py
& $python WorkOrder/verify_camera_transition.py
& $python WorkOrder/verify_camera_resolution.py
& $python WorkOrder/verify_fingers.py
& $python WorkOrder/verify_five_lane_input.py
& $python WorkOrder/verify_emg_serial.py
& $python WorkOrder/verify_full_song.py
powershell -ExecutionPolicy Bypass -File build_windows.ps1
& ".\dist_windows\EMG-Motion-Rhythm\EMG-Motion-Rhythm.exe" --self-test release/self-test.json
```

- 수정 파일 및 커밋, 최초 재현·수정 후 화면, 설정 저장 전후 창·중앙 위젯 크기와 배율 비교, 원인과 수정 근거, 기준판/수정판 측정표, 실패·미검증 조건을 정리한다.
- 실행 ZIP·SHA256·자체 검사 JSON, 전시 해상도·카메라·입력 설정, 테스트한 전시 곡과 채보, 장치 실패 시 복구 절차를 전달한다.
- 구조 참고는 [손 커서 다이어그램](https://github.com/didtjr5080/Rythm-Game/blob/42bc7ec/diagrams/hand-cursor.md)과 [데이터 흐름 다이어그램](https://github.com/didtjr5080/Rythm-Game/blob/42bc7ec/diagrams/data-flow.md)을 GitHub에서 연다. 구조 그래프를 직접 갱신할 때는 활성 가상환경에 `pip install graphifyy` 후 저장소 루트에서 `graphify .`를 실행한다.
