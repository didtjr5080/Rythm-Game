# 카메라와 게임 프레임 지연 최적화

EXTRACTED: v2026.11.09.3부터 [카메라 수명 관리](camera-transition-crash.md)를 보완했습니다. 화면 사이에는 같은 작업을 재사용하며, 장치 변경에 따른 종료와 새 연결도 겹치지 않습니다. 화면은 네이티브 해제를 기다리지 않지만 앱 최종 종료 시에는 작업 정리를 기다립니다.

EXTRACTED: 게임·로비·보정·설정 미리보기의 카메라 읽기와 MediaPipe 추론은 `LiveVideoWorker`의 작업 스레드에서 실행합니다. GUI 스레드는 최신 결과 한 개만 읽으며 카메라 드라이버나 추론을 기다리지 않습니다. Qt 이미지와 화면 그리기는 GUI 스레드에서 유지합니다.

EXTRACTED: 작업 결과는 촬영 시각 기준 250ms 이후 만료되며, 좌우 반전을 바꿔도 이전 방향의 결과는 사용하지 않습니다. 카메라와 MediaPipe는 작업 스레드가 종료 시 직접 정리합니다. 화면 전환은 카메라 드라이버를 기다리며 정지하지 않습니다.

EXTRACTED: 손 인식용 이미지만 가로·세로 중 긴 쪽 최대 640픽셀로 줄입니다. 표시용 카메라 해상도와 게임 화면 해상도 설정은 유지합니다. 손이 보이면 최대 30Hz, 보이지 않으면 최대 15Hz로 처리합니다. GUI 타이머는 기존 60FPS 설정을 사용하며 정밀 타이머를 적용했습니다.

EXTRACTED: 같은 영상의 RGB 변환과 게임 카메라 픽스맵 생성을 재사용하고, 사용하지 않는 디버그 축소 복사본은 만들지 않습니다. 채보는 시간으로 정렬하고 이진 검색으로 화면에 보이는 구간만 그립니다. 판정은 다음 미판정 노트부터 진행합니다. 음악 재생 시각·판정 허용 구간·수축당 한 번 입력·5레인 매핑은 유지합니다.

검증:

- `WorkOrder/verify_live_video.py`: 인위적으로 느린 카메라 30ms와 추론 50ms를 사용했습니다. 동기 처리 기준 약 80ms에 비해 최신 결과를 읽고 입력을 합치는 경로의 p95는 0.005ms였습니다. 이는 모의 지연 환경에서의 입력 경로 비교이며 실제 캠 FPS 수치가 아닙니다.
- 오래된 손 결과 차단, 반전 결과 무효화, 작업 중 종료 요청, 작업 소유 스레드의 자원 해제, 10만 노트 구간 검색을 검증했습니다.
- 손가락 32가지 조합, EMG 오입력 차단, 수축당 한 번 판정, 음악 전체 재생, 1920×1080·1440×900 화면을 검증했습니다.
- EXE 자체 검사에서 Qt와 함께 실제 MediaPipe 추론을 작업 스레드에서 실행하고 종료를 확인합니다.

AMBIGUOUS: 현재 실행 환경에서 카메라 0을 열 수 없어 물리 카메라를 켠 상태의 최종 FPS와 손 인식 정확도는 현장 재확인이 필요합니다. 장치 드라이버가 읽기에서 멈추면 작업 스레드는 읽기가 돌아온 뒤 자원을 해제합니다.
